# 📝 Customer Discovery Interview Analyzer Skill

This skill provides an automated, rigorous methodology for ingesting, analyzing, and synthesizing individual qualitative customer discovery interview markdown files (generated by `5_Symbols/cd/cd-interview-recording.html` or located in `3_Simulation/Interviews/` and `~/Downloads/`).

## 🎯 Purpose & Scope

When a new customer discovery interview markdown file (e.g. `interview_apo_2026-08-18.md`, `interview_baran_g_2026-08-18.md`) is provided, this skill guides the AI agent to:
1. **Extract Structured Interview Fields & Privacy Guardrail**:
   - **Privacy Rule:** Strictly use **first names only** (e.g. `Sude`, `Brian`, `Bora`, `Charles`, `Marianna`, `Mehmet`, `Cheuk`, `Faruk`, `Jamal`, `Tomiwa`, `Erdem`; candidate B. as `B.`). Never include last names when ingesting, archiving, analyzing, or citing feedback.
   - Candidate Name (First Name Only), Date, Channel / Watering Hole (e.g. F2F Cambridge, Teams, LinkedIn, Live Cohort), Referral Source.
   - Tagged Hypotheses (e.g. H1, H24, H25, H29, H30).
   - 1. Day-In / Day-Out (Routine & Habits).
   - 2. Current Workarounds (How they solve it today without our product).
   - 3. Past Actions & Stories (Concrete past events, failures, or attempts).
   - 4. Key Pains Identified (Friction, time scarcity, cognitive overload, lack of assets).
   - 5. Key Gains Identified (Time recovery, revenue uplift, presentability, confidence).
2. **Evaluate Methodological & Strategic Alignment**:
   - Compare findings against Steve Blank's Customer Development framework.
   - Determine whether candidate represents Persona 1 (Student/Jobseeker), Persona 2 (Practitioner/SRE), Persona 3 (Enterprise Lead), or Persona 4 (Independent Contractor / FDE).
   - Cross-check against the **Signal vs. Noise** principle and **Listening Mandate** (H29).
3. **Automate Repository Synchronization**:
   - Archive raw markdown under `3_Simulation/Interviews/interview_[name]_[date].md`.
   - Publish a versioned Markdown analysis report: `reports/customer-discovery-[name]-interview-v1.0.0.md`.
   - Update `5_Symbols/cd/archived-interview-transcripts.html` with a styled discovery card.
   - Update `5_Symbols/cd/cd-interview-recording.html` archive grid.
   - Register report in `nav.js` (Docs dropdown & Search Index).
   - Bump `HYPOTHESIS.md` version and append a changelog entry linking to the new evidence.

## 🛠️ Step-by-Step Execution Workflow

### Step 1: Ingestion & Parsing
Run the helper Python script to parse the interview markdown file into structured JSON:
```bash
python3 .agents/skills/customer-interview-analyzer/scripts/parse_interview_markdown.py --file 3_Simulation/Interviews/interview_apo_2026-08-18.md
```

### Step 2: Qualitative Analysis & Hypothesis Mapping
Analyze the extracted fields against the 29 tracked business hypotheses:
- **H1 / H25 (Skills vs Credentials):** Are they seeking knowledge/revenue leverage, or purely an exam badge?
- **H2 / H10 (Pedagogical Format):** Do they prefer visual analogies/storyboards over dry docs or dense infographics?
- **H3 / H21 (Willingness to Pay):** What budget or financial threshold was mentioned?
- **H24 (Emotional Drivers):** Is time pressure, fear of obsolescence, or chaos driving action?
- **H29 (Listen > Speak):** Did founder practice active listening without pitching solutions?
- **H30 (FDE / Contractor Roadmap):** Does the candidate value operational toolchains (Second Brain, scripts, CLI) to generate revenue?

### Step 3: Publish Versioned Report
Create `reports/customer-discovery-[name]-interview-v1.0.0.md` with:
- Executive summary of findings.
- Structured intake table (Verbatim quote vs Practitioner Reality).
- Strategic business & hypothesis impact analysis.
- Concrete action items for Sunday live cohort curriculum.

### Step 4: Update Repository Hubs & Deploy
1. Append an interview card to `5_Symbols/cd/archived-interview-transcripts.html`.
2. Append a quick-link card to `5_Symbols/cd/cd-interview-recording.html`.
3. Add entry to `nav.js` `searchIndex` and Docs dropdown.
4. Update `HYPOTHESIS.md` version and change log.
5. Commit and push to GitHub `origin main`.
6. Open updated pages in Chrome for post-task verification.
