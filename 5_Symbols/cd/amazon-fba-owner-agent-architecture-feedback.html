📦 Amazon FBA Owner — Determinism, Relational Memory & Telegram-Managed Agents

A Turkish-speaking Amazon FBA operator, running his store on scripts he wrote himself, will not hand critical processes to non-deterministic AI — and independently described our own stack as his ideal: autonomous agents over a relational memory (PostgreSQL/Supabase), installed on an always-on local machine, driven from Telegram. Verbatim report: Report v1.0.0 · Raw interview

Attribution caveat: participant unnamed; session logged in Turkish and translated. Directional input, not validated named field evidence. No status tier changed; confidence holds 49 / 100.

🗣️ Translated Highlights

"Predictability is the biggest problem. Classical code is deterministic; whatever task you give it, it does the exact same thing every time. AI behaves non-deterministically. One day it gives a great result, the next day it asks absurd questions or produces wrong output."
"I cannot hand over the critical processes of my Amazon store to AI with my eyes closed, so I prefer to run the core logic with stable code and use AI only in specific areas."
"Should I build every job as separate modules/boxes, or set up one main brain software that governs everything? I want my systems to learn my working style and do the work without me constantly re-explaining the same context."
"Instead of keeping data in simple tables, I am moving to relational databases like PostgreSQL or Supabase… Before an automation acts it will look at the database, understand what was done in the past, and take the new step accordingly without tiring me unnecessarily."
"Installing the agent on a local computer or server that is always on, so I can manage all my business remotely… check Amazon metrics every 4 hours, review ad profitability, or reply to incoming messages. Instead of wasting time in the menus of different applications, one agent interface running everything in the background."

🧭 Where Our Business Model Lines Up With The Operator

Deterministic core, bounded AI

The buyer keeps revenue-critical logic in stable code and admits AI only where a wrong output is cheap to catch. Our guardrail content (thin deterministic core, governed agent zones, sandbox before release, Lean CTO / Strict CFO discipline) answers this directly.

Modules vs one main brain

An unresolved orchestration question in a live business: separate boxes or a governing control plane? This is a curriculum module, not an FAQ — and a reusable discovery probe.

Memory = an auditable ledger

To an operator, "permanent memory" means PostgreSQL/Supabase state an automation consults before acting — not chat history. Lead with the ledger when teaching agents.

Always-on box, Telegram control plane

Agents, not raw LLMs; converted always-on laptop/server; scheduled 4-hourly metric jobs; one interface instead of app menus. The operator reached our tooling thesis unprompted.
